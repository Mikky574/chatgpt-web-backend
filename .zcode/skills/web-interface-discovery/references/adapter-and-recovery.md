# 调用适配与恢复契约

## 业务身份先于页面位置

建议分开持久保存站点/账号上下文别名、可选项目、任务、原网页对象ID、每次请求ID、网页轮次/作业ID和产物。实际需要哪些层由应用决定，不能因为示例有项目就强制创建项目。

登录状态与业务上下文是两回事：同一账号可能有多个项目/对话，同一个URL在另一个账号中可能无权限。同一任务后续沿用已验证的业务对象；URL名称slug可按已验证规则规范化，但保留稳定ID，不能截断到所有项目共享一个ID。创建过程中出现的临时URL不作为最终身份。

关闭标签页可以后台重开原地址；有多个候选账号、相同对象重复页或已绑定页导航到另一个有效任务时，不猜测。新建后台页核对CDP target身份；用户界面不应因每轮调用抢焦点。站点明确无权访问且业务允许重建时，记录from/to及上下文丢失，只携带当前批准输入；不自动搬运旧账号数据。审批、支付、部署等操作不能套用“失效就新建并再提交”的对话策略。

## 状态与接口

只有任务耗时长、要恢复或需要并发时才使用作业接口；简单同步查询不强制排队。一个可用的异步约定是：

```text
POST /jobs          提交一次；返回request_id与queued/running
GET /jobs/{id}      查询status、stage、业务对象、部分/最终结果
GET /jobs/{id}/events  可选SSE；标明生命周期事件还是实际增量
POST /jobs/{id}/recover  查询原对象，不重新提交
```

状态可包含queued、locating_context、filling、submitting、submission_confirmed、running、awaiting_user_input、completed、failed、interrupted、unknown。HTTP响应是否成功、业务是否受理、结果是否完整、是否需要人确认、整个任务是否结束分别表达。

网页提交成功至少有一项站点实际业务证据：本次消息/对象出现、服务端ACK或有身份关联的job。输入框清空、Enter返回或按钮变灰只能作辅助证据。若提交不确定，保存原request_id与现场，不能新ID重发。

重复request_id与相同规范化内容返回原作业；内容、项目或账号范围不同则冲突。客户端幂等只防止本服务重复执行；服务端缺少幂等能力时，不能宣称断线后绝不重复产生副作用。进程中断后的未完成任务标记unknown/interrupted，先恢复查询。

## 并发与busy

按实际共享资源锁定：同一网页对象串行，操作同一个页面的UI动作互斥；独立HTTP请求只有在协议与账号限制允许时才并行。创建项目、刷新、下载等若会导航同一页面，也要参与同一互斥机制。

队列设置上限与等待截止时间，返回队列位置、当前阶段及request_submitted标记。尚未受理的busy/capacity拒绝可等待后重新尝试；已经受理或无法判断时只能查询原ID。不要通过开更多标签页或换对话来掩盖busy。

## 错误策略

| 条件 | 行动 | 不做 |
| --- | --- | --- |
| 提交未确认、响应丢失 | 查询原对象/请求；必要时提示核对 | 盲目换ID再提交 |
| 网站明确要求刷新 | 在身份、草稿、活动任务保护条件满足后有限刷新 | 对每次超时无差别reload |
| 原轮次明确提供Retry | 按业务规则重试该轮，记录次数与意图 | 重发整个任务或点其他轮次 |
| 未登录/认证过期 | 正常刷新身份或让用户重新登录，再恢复原对象 | 导出Cookie到外部服务 |
| 无权访问/对象不存在 | 按已授权业务策略终止、重新选择或重建 | 对所有业务自动创建替代对象 |
| 限流/维护/5xx | 按Retry-After与有界退避；先确认写入是否受理 | 无限循环或换账号规避 |
| 需要确认/澄清 | 展示原提示与操作选项 | 将文字启发式误报当成已审批 |

重试、刷新、重建分别计数并设置与风险相称的上限；恢复成功清理过期错误标记，失败保留原身份和证据。

## 文件与完成判定

文件链接出现不代表产物下载成功。关联原任务和文件ID，检查响应状态、Content-Type、大小及必要内容；登录HTML即使200也不是报表。短期签名URL留在运行时，报告只显示文件别名和本地安全路径。下载403先区分过期、权限、验证或服务错误，不重新生成业务任务来代替下载恢复。

模型/页面文字说“完成”不是独立执行证据。验收应对照实际对象、退出状态、测试结果或下载内容；多轮结果可能受网站记忆、默认项目指令或模型幻觉影响。运输层身份正确与业务回答正确分别验证。
