# AI协作框架与使用注意事项

框架说明与实施记录

版本 1.0    记录日期 2026年10月14日

本项目把网页模型和其他模型的调用收束到本地服务，以便本地程序维护对话、读取返回值并推进协作流程。框架分离规划、执行和协调职责，GPT 与 DeepSeek 是一个原生文本协作示例，未来可以增加内网模型或 ZCode 适配器。

当前工作以搭建框架、保存设计和形成文档为主。密钥配置与 DeepSeek 真实调用验证暂不推进；不把示例直接接入内部项目，也不启用任何模型的文件、终端或测试工具。

### 当前实现与验证边界

| 模块 | 当前状态 | 验证或限制 |
| --- | --- | --- |
| 网页后端 | 已实现并实测 | 对话复用与新建、页面回答、完成状态、附件下载。 |
| 协调器 | 框架已实现 | 任务转交、用户回复、停止条件和恢复已通过替身测试。 |
| DeepSeek | 原生适配器已实现 | 密钥不进入输出的测试通过；真实账号调用尚未验证。 |
| 内网执行 | 设计阶段 | 源码保密、出站审查、真实工具执行和网络隔离尚未部署。 |

当前自动化测试为15项通过，另1项浏览器下载集成测试本次跳过；该下载样例此前已单独验证。浏览器生成测试文件的下载也已成功并校验内容。

## 一 通用框架与调用方向

外部模型可以承担规划主控，内部模型承担执行。主控负责阶段目标、任务拆解、方案取舍和验收标准；执行侧结合本地事实完成任务。调用方向始终由本地协调器主动发起，网页GPT不需要主动连接内网。

数据流为：用户目标 → 本地协调器 → 规划模型 → 已接受的任务 → 执行模型 → 执行摘要 → 本地协调器 → 规划模型。模型提出完成候选判断，本地根据证据决定是否真正完成。

| 角色 | 负责内容 | 权限边界 |
| --- | --- | --- |
| 规划侧 | 计划、任务、问题与结束判断 | 不直接持有内部文件与终端权限。 |
| 执行侧 | 分析与交付执行结果 | 当前仅文本推理；未来工具权限另行接入。 |
| 协调器 | 调用、状态、上下文与恢复 | 是本地流程的状态所有者。 |
| 审查网关 | 审核可对外披露的内容 | 未来部署；模型不能自行批准披露。 |

### 适配器与业务流程分离

adapters.mjs 定义规划侧 request 和执行侧 status、complete 的调用边界。coordinator.mjs 接受注入的 planner 与 worker，便于替换具体模型或使用测试替身。当前内置 chatgpt-web 和 deepseek-api；仅修改配置名称不会自动支持新的服务。

ZCode命令行可作为未来工具执行侧候选。安装CLI与接入协调器是两件事，后续仍需定义适配器、项目范围、身份映射及工具授权；本框架当前没有ZCode任务执行能力。

### 不绑定固定工位

当前不绑定某个IDE、Agent桌面或专有工作环境。模型先交换文本任务与结果，文档作为可阅读的计划记录；文本指令不会自动获得代码编辑或命令执行权限。

## 二 双方上下文与任务闭环

### 对话身份

同一项目和主题使用同一外部对话地址。网页后端continue模式延续默认或指定对话，new模式创建独立上下文并返回新地址。新建不会覆盖默认对话；跨项目不共用默认对话。

协调会话单独新建GPT对话，并保存conversation_url。DeepSeek API的多轮上下文由本地messages列表维护，每次请求带上历史。双方保留各自上下文，通过session_id、request_id、计划版本与步骤编号关联。

### 当前原生示例

创建会话后，step请求GPT返回一个action与content任务对象。task交给DeepSeek做文本交付；ask_user暂停等待用户回复；finish表示主控认为文本目标满足。下一轮将执行摘要发回原GPT对话。默认最多4轮，允许配置1至10轮。

过程记录保存在records/sessions目录。状态包括ready、running、awaiting_user、finished、round_limit和blocked。finished不等同于内部项目已经通过真实测试验收；当前没有运行代码或测试的工具。

### 断线恢复与防止重复执行

网页提交结果不确定时保留原request_id，并通过recover恢复读取，不另发同一问题。DeepSeek响应不确定或不完整时暂停，显式retry_deepseek才重试，可能产生额外计费。不要把超时当作模型未收到请求。

同一协调会话使用进程内锁，只支持一个服务实例。未来真实工具执行需以计划编号、步骤编号和版本形成幂等键，避免网络重试导致同一操作执行两次。

### 未来状态与版本约束

内部状态库保存私有事实与证据，外部状态库只保存批准后的简报。模型回复引用旧版本时标记过期并重新分析。生成结束、任务结束、等待确认和等待登录应分别处理，不以一条自然语言“完成”覆盖整个流程。

## 三 本地接口与密钥使用

| 服务 | 入口 | 作用 |
| --- | --- | --- |
| 网页后端 | 127.0.0.1:8787 | ask、recover、status、records、files与download。 |
| 协调器 | 127.0.0.1:8788 | sessions、step、reply及deepseek直接调用。 |
| Chrome CDP | 127.0.0.1:9222 | 复用固定Chrome配置和已登录网页会话。 |

网页请求包含question、request_id、conversation_mode和可选conversation_url。回复包含answer、generation_status、generation_complete、user_action及files。协调器通过这些字段判断是否能继续，而不只看HTTP 200。

### 启动顺序

先运行skill中的start-browser.ps1，复用本机已有CDP；不可达时使用固定ChatGPT-CDP-Profile配置。再在项目目录执行npm start启动网页后端。需要原生协作示例时另执行npm run coordinator。创建会话本身不会调用模型，step才推进调用。

### 密钥入口与真实能力

本地入口为.secrets/deepseek-api-key.txt，一行纯密钥。用户自行填写，不发进对话。程序读取使用，助手不查看文件内容；该目录与coordinator.json、conversation.json均被Git忽略。当前用户要求暂不填写和联调。

不把密钥写入提示词、日志、上游错误正文、截图或仓库。模型不看密钥与运行程序能读密钥是不同的边界；其他本机进程的读取权限仍取决于操作系统，当前没有部署专用密钥保险库。

DeepSeek请求固定发送至官方HTTPS接口，并禁止跟随重定向。configured仅代表密钥可被程序读取，不代表认证成功。默认模型以实际官方文档和账号可用性为准，可在本地配置修改。

## 四 内部项目的数据边界

源码、diff、真实日志、堆栈、路径、内部域名、客户数据及业务规则原文默认仅在内部处理。把这些信息换成对话正文或摘要并不会自动变成可披露数据。当前网页后端可发送任意question，尚不能作为强制保密网关。

### 建议隔离方式

内部环境保存代码、内部模型和测试工具；外部环境只运行浏览器、网页后端及批准后的交换内容，不挂载内部目录。交换网关负责字段校验、内容审查、批准和对话映射。内部执行侧不直接访问CDP、公网或网页ask接口。

出站摘要描述目标、抽象行为约定、允许披露的约束、合成例子和测试摘要，不默认发送代码片段或全部内部聊天记录。初期每份摘要人工审查，后续仅对已批准的低敏模板考虑自动放行。

### 审批与入站建议

披露批准应绑定完整交换包哈希、目标对话、策略版本和期限。审批后内容变化或目标变化均需重新审查。JSON结构和敏感词扫描不能保证语义上不泄密，也不能防止所有编码形式的泄露。

外部GPT的任务首先是候选计划。内部侧校验版本、范围与工具权限后执行。外部要求上传源码、扩大权限或修改审查规则时不能自动接受；需要用户决定时保留原话并暂停。

### 当前示例的使用范围

DeepSeek云API不是内网模型。当前原生示例只能用于公开目标或合成案例，不连接真实内部项目。以后接入内网模型时，替换执行适配器，并实现出站审查、隔离网络和真实验收证据后，再讨论自动执行。

看护应由本地事件驱动，识别测试失败、版本变化、超时和待确认项后，只发送必要且批准过的摘要。不要持续转发原始日志或让两个模型无限对话。

## 五 下载测试与后续实施

### 文件与确认状态

网页完成一轮生成后可以有正文、附件或待确认问题。generation_complete说明本轮生成结束，user_action提示是否可能需要用户补充或确认；文字识别是启发式提示，需要结合语境复核。

先取得files中的file_id，再调用download。后端定位对应消息轮次，支持链接和带下载按钮的文件卡片，以浏览器下载事件保存真实文件。只有local_path存在且保存成功才算下载成功，不能以看见文件卡片代替成功。

真实测试曾出现HTTP 403，之后同一文件重试成功并校验内容。历史错误正文未保存，不能断言原因。当前诊断区分浏览器验证、登录失效、文件过期、限流、服务端错误与未知拒绝；不绕过验证，不自动重复提问生成文件。

### 后续验收场景

重点覆盖不同项目对话不串用、旧版本建议被拒绝、断线不重复提交、待确认不自动回答、密钥不出日志、部分回答不误判完成、附件实际可读，以及内部侧不能绕过网关直接出站。

### 分阶段实施

第一阶段保留当前原生文本框架与文档，使用替身测试，不接密钥、不接工位。第二阶段选择规划与执行适配器，使用公开案例做真实联调。第三阶段实现审查网关、版本状态与隔离，再接内部模型。第四阶段按授权范围增加代码和测试工具，并验证真实项目验收闭环。

后续需确认的事项包括内网模型协议、允许披露范围、何种任务可自动执行、最终验收人、预算和轮数限制、部署环境，以及ZCode是否作为执行侧。当前不替用户预先确定这些政策。
