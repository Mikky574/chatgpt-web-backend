# 主控手与操作手的分工

技能入口：.zcode/skills/controller-operator/SKILL.md。调用方式：$controller-operator 帮我完成：你的任务。

明确且已授权的常规工作由操作手直接完成。需求歧义、方案取舍、阶段目标和异常判断交给主控。主控实际分配的任务必须回传具体反馈，但不为每条命令咨询或请求盖章。

主控给一个有边界的任务：目标、授权范围、可验证完成条件和停止条件。操作手核对后实际实施和测试。主控根据反馈判断缺少证据、补验证、调整计划或结束。双方不需要知道对方具体模型身份。

## 反馈与幻觉控制

按“要求 → 实际行为 → 本地证据 → 状态”逐项回报。状态区分完成、部分完成、未验证、阻塞。说明输入类别、预期与实际、退出状态和未覆盖条件，避免只有通过数量。未运行就写未运行；假设不能写成事实。

核对实际文件、改动、测试报告和退出状态，矛盾时事实优先。主控无法访问实现时不能独立核验，信息不足要明确还缺什么。当前脚本只校验消息和对话状态，尚未实现独立执行证据核验或工具沙箱，不能保证消除幻觉。

## 消息格式

本地packet.json用于字段检查和任务关联，发送前转Markdown。task_id、request_id和URL只在本地记录，不发送固定角色介绍。可选字段constraints、observations、questions、project_structure、file_roles、symptoms、expected_behavior、evidence、hypotheses、options、unknowns；只填有关内容，不凑模板。

故障咨询说明现象、预期、证据、假设、候选方案和具体疑问。主控贡献反例、取舍依据或区分原因的验证，不复述结论。示例见 [因果咨询](../examples/causal-consultation.json)。

例如：本轮要求避免串答；实际排除折叠控件，保留严格匹配与消息ID锚定；恢复原请求读到已有回答，共享前缀负例不匹配；其他虚拟化布局未覆盖。请主控决定是否补充该场景及最小测试条件。这比“所有测试通过，请确认”更有价值。

用户可在操作手对话补充需求，下一轮仅发送可披露的新约束。固定task_id复用原对话，未知提交先recover不重发。配置由role-collaboration.json或示例文件选择。

允许经检查的相对结构、模块关系、文件用途和行为概括。禁止凭据、Cookie、客户数据、未批准源码与原始日志。内部摘要仍须符合组织披露规则；常见凭据扫描不能识别全部敏感内容，本技能不是强制保密网关。
